# Product-owned Telegram credential for fresh 0x1 Identity

`TELOXIDE_TOKEN` for `@nilxone_bot` is a **product secret**:
`nilx-one/web` → **Settings → Environments → production → Secrets**.
It must **never** be copied into `aiaiaiai-org/infra` secrets,
GitHub workflow dispatch input, shell argument, or public log.

The product has one **non-secret** environment variable,
`EDGE_DEV_1_IDENTITY_AGE_RECIPIENT`. It is the `age1...` public
recipient generated by the sole VPS `edge-dev-1`, not an SSH host
fingerprint or a public `ssh-ed25519` host key.

After that variable and the product's genuine bot token are available,
run `Package fresh 0x1 Identity secret envelope` manually on the
product's trusted `master` branch. It validates the format, encrypts
**only** `TELOXIDE_TOKEN` using AGE, and publishes an
attested immutable digest under
`ghcr.io/nilx-one/0x1-identity-fresh-secrets@sha256:...`.

The product's job summary prints only the **encrypted OCI image
reference**, never the token. Infra verifies the producing workflow and
signature on that exact digest. It transports the ciphertext to
`edge-dev-1`, where the VPS-owned AGE private key alone decrypts it.
Neither Infra GitHub Secrets nor Infra's Actions runner ever receives
the plaintext bot token.

The current Rust Identity binary also runs a Telegram dispatcher.
Ensure there is exactly one active `getUpdates` consumer for the
`@nilxone_bot` token before enabling the fresh Identity container.
No Market issuer or purchase worker is enabled in this bootstrap.

The product token is independent of AIS credentials:
`auth.aiaiaiai.org` is the ecosystem identity issuer; 0x1's fresh
product profile database is on the VPS. This does not restore any
historical Bond, Avaia, wallet or Relationship.
