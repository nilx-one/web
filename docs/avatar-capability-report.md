# Avatar motion baseline (P0)

Inspected Web baseline: `8f1aebf`. This is the first small PR in the avatar
autorig/motion plan: inventory tooling, baseline assessment, and CI evidence.
The existing generated studies already have rigs; they should not be replaced
or automatically rebound just because the broader plan includes auto-rigging.

## Observed ownership

| Surface                                   | Existing implementation                                            |
| ----------------------------------------- | ------------------------------------------------------------------ |
| Asset authoring                           | `tools/avatars/{sky,dasha,kai,dasha2}/build_model.py`              |
| Skeleton, skin weights, clips, GLB export | `tools/avatars/rig.py`                                             |
| Bind cancellation, weights, shared clips  | `tools/avatars/test_rig.py`                                        |
| Model and wardrobe selection              | `packages/application/src/avatar-appearance.ts`, `avatar-scene.ts` |
| Map loading and playback                  | `packages/map-maplibre/src/avatar-layer.ts`                        |
| Editor loading and playback               | `packages/graphics/src/avatar-preview.ts`                          |

Both renderers use Three.js `GLTFLoader`, `SkeletonUtils.clone`, and
`AnimationMixer`. Generated assets are same-origin, versioned GLBs; their
sources and expected SHA-256 values are tracked, their generated bytes are not.
Core has no ownership of this asset-inspection tool. The protocol boundary is
unchanged: presentation motion is not evidence of a completed bilateral
interaction and creates no BondChain.

## Existing rig and clips

| Asset     | Version | Skeleton                          | Clips                                    |
| --------- | ------- | --------------------------------- | ---------------------------------------- |
| Sky       | 0.1.0   | Shared 22 nodes                   | idle, walk, turn_in_place, wake, quiesce |
| Dasha     | 0.1.0   | Shared 22 nodes                   | Same five                                |
| Kai       | 0.1.0   | Shared 22 nodes                   | Same five                                |
| Dasha 2.0 | 0.3.0   | Shared 22 nodes; modular wardrobe | Same five                                |

The topology has one ground root plus 21 deforming bones, including shoulders.
Authoring is Z-up and export converts positions, normals, joints and bind
matrices together to Y-up. Clip tracks are shared local rotations with no
translation root motion. Landmark-derived local translations define each
model's bind pose. Asset-specific left/right names such as `upperarm_L` and
`thigh_R` need explicit mapping to the proposed semantic rig names; a new
contract must preserve the existing immutable asset paths and bytes.

The generated rig is a candidate source for canonical mapping. No separate
external donor was supplied with this plan, and no donor has been qualified
for humanoid retargeting. Presence of joints alone does not establish that.

## Reproduce the machine-readable evidence

After the documented [asset build](avatar-rendering.md#build-and-verification):

```sh
python tools/avatars/test_inventory.py
python tools/avatars/inventory.py deploy/web/avatars --output /tmp/avatar-inventory.json
```

The standard-library-only inspector walks all `.glb` files in sorted relative
path order. It records source SHA-256, byte size, nodes/rest transforms, skin
bindings, joint names, inverse-bind accessor metadata, mesh attributes, morph
target counts, material/texture counts, required extensions and animation
channels. It never changes the inputs. Output has no timestamp or absolute
workspace path and is deterministic for identical inputs.

An empty directory, unreadable file, malformed container/JSON, or invalid
inspected reference returns a nonzero exit code. Per-model errors remain in
the report alongside successful inspections. `status: inspected` means only
that this metadata inspection completed: accessor payloads, compression,
external resources and deformation are not validated by this tool. Existing
rig tests remain the numeric gate; Khronos validation and visual QA remain
separate future work.

Full CI generates the report from the same assets it already builds/verifies
and retains `avatar-inventory-<commit>` for seven days, including a partial
report when inspection fails. It does not rebuild models for inspection or
include the report in the deployed client package.

## Next small PRs

Each PR should contain one to three tasks and one independently reviewable
result. This PR does not complete all of P0 or claim completion of P1–P16.

1. **Canonical mapping:** document semantic bones and coordinate/rest-pose
   conventions; map the existing study rig; test mapping invariants.
2. **Diagnostic deformation:** deterministic diagnostic poses; numerical
   deformation metrics; phone-viewable pose sheets. Choose one target from
   this evidence before extending or rebinding it.
3. **Motion contract:** locomotion versus one-shot action state; root-motion
   ownership; deterministic transition tests. Inspect existing Avaia motion
   behavior before adding a second state machine.

Run/crouch/jump/fall/get-up/dance clips, general donor extraction and
retargeting, arbitrary target fitting, IK and body-part control are not
established by this inventory. Good deformation, terrain response and phone
performance still require their own evidence. A separate donor's skeleton,
weights and rest pose must be inspected once that donor is accessible.
